Containers
Docker
Containerization Engine

Package your application and all its dependencies into a lightweight, portable container that runs identically on any machine — eliminating "works on my machine" forever.

  • Build once, run anywhere on any OS
  • Isolated environments per service
  • Docker Compose for multi-container apps
  • Docker Hub registry for image sharing
# Dockerfile example
FROM node:18-alpine
WORKDIR /app
COPY . .
RUN npm install && npm run build
CMD ["node", "server.js"]
▶  Expand full tutorial
01
Understand Images vs Containers: An image is a read-only blueprint. A container is a running instance of that image — like a class vs object in code.
02
Layered Filesystem: Every Dockerfile instruction creates a cached layer. Docker only rebuilds changed layers, making builds blazingly fast.
03
Networking: Containers communicate via bridge networks. Use docker network create to connect services, or use Docker Compose which auto-creates a shared network.
04
Volumes for Persistence: Containers are ephemeral — data dies with them. Mount volumes with -v ./data:/app/data to persist databases and file uploads.
☸️
Orchestration
Kubernetes
Container Orchestrator

Automatically deploy, scale, and heal containerized applications across a cluster of machines. Kubernetes handles scheduling, load balancing, rolling updates, and self-healing.

  • Auto-scaling with HPA & VPA
  • Zero-downtime rolling deployments
  • Self-healing: restarts failed pods
  • Service discovery & load balancing
# scale deployment
$ kubectl scale deploy/myapp --replicas=5
# rolling update
$ kubectl set image deploy/myapp \
  app=myapp:v2.0
# check pod status
$ kubectl get pods -w
▶  Expand full tutorial
01
Core Objects: Pods (smallest unit), Deployments (manage pods), Services (stable networking), ConfigMaps/Secrets (configuration). These 4 cover 80% of real-world K8s.
02
Declarative Model: Write YAML describing desired state. K8s control loop continuously reconciles reality with desire — this is how self-healing works.
03
Ingress: Route external HTTP traffic to internal services. Combine with cert-manager for automatic TLS certificates from Let's Encrypt.
04
Namespaces: Partition a single cluster into virtual clusters. Use separate namespaces for dev/staging/prod to share infrastructure safely.
🔄
CI/CD
GitHub Actions
Continuous Integration

Automate every step of your software workflow — testing on every commit, building containers, deploying to cloud — all defined as code in your repository.

  • Triggered on push, PR, schedule, or API
  • Matrix builds: test on multiple OS/versions
  • 6000+ reusable actions marketplace
  • Secrets management built-in
on: [push, pull_request]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
     - uses: actions/checkout@v4
     - run: npm test
     - run: docker build .
▶  Expand full tutorial
01
Workflows, Jobs, Steps: A workflow contains jobs that run in parallel by default. Jobs contain steps (shell commands or actions) that run sequentially.
02
Environment Protection: Require manual approval before deploying to production. Create environments in repo Settings with required reviewers.
03
Caching: Cache node_modules, pip packages, or Docker layers between runs with actions/cache to cut CI times by 70%.
04
Reusable Workflows: Extract common pipeline patterns into reusable workflows. Call them from multiple repos to standardize CI across your org.
🏗️
IaC
Terraform
Infrastructure as Code

Define your entire cloud infrastructure — servers, networks, databases, DNS — as version-controlled code. Provision and tear down environments in seconds, repeatably.

  • Multi-cloud: AWS, GCP, Azure, 1000+ providers
  • State tracking detects drift automatically
  • Plan phase previews changes before apply
  • Modules enable reusable infrastructure
resource "aws_instance" "web" {
  ami = "ami-0c55b159cbfafe1f0"
  instance_type = "t3.micro"
  tags = { Name = "prod-web" }
}
$ terraform plan
$ terraform apply
▶  Expand full tutorial
01
State File: Terraform keeps a terraform.tfstate mapping resources to real infrastructure. Store it remotely in S3 with DynamoDB locking for team use.
02
Plan Before Apply: Always run terraform plan first. Read every line — it shows exactly what will be created, modified, or destroyed.
03
Workspaces: Use workspaces or separate state files for dev/staging/prod. Never share state between environments.
04
Data Sources: Query existing infrastructure with data blocks. Fetch AMI IDs, VPC settings, or certificate ARNs dynamically instead of hardcoding.
📜
Config Mgmt
Ansible
Configuration Management

Agentless automation using simple YAML playbooks. Configure servers, deploy applications, and orchestrate complex multi-tier workflows — all over SSH, no agent required.

  • Agentless — only SSH required on targets
  • Idempotent tasks — safe to re-run
  • 3000+ built-in modules for any task
  • Ansible Galaxy — community roles library
# site.yml playbook
- hosts: webservers
  become: yes
  tasks:
  - name: Install nginx
    apt:
      name: nginx
      state: present
▶  Expand full tutorial
01
Inventory: Define your servers in an inventory file grouped by role (webservers, dbservers). Use dynamic inventory for cloud providers to auto-discover hosts.
02
Idempotency: Run a playbook 10 times safely — it only changes what needs changing. The state: present pattern is the key: describe desired state, not actions.
03
Roles: Structure complex playbooks into reusable roles with tasks, handlers, templates, and defaults. Pull community roles from Ansible Galaxy instead of reinventing.
04
Vault: Encrypt secrets (passwords, API keys) with ansible-vault encrypt_string. Commit encrypted values safely to git.

Observability
Prometheus + Grafana
Monitoring & Alerting

Collect time-series metrics from every service with Prometheus's pull model, then visualize trends, anomalies, and SLOs on stunning Grafana dashboards. Alert before users notice.

  • PromQL — powerful query language
  • Alertmanager for on-call routing
  • Grafana dashboards with live data
  • RED method: Rate, Errors, Duration
# PromQL: error rate
rate(http_requests_total{
  status=~"5.."
}[5m])
# Alert rule
expr: error_rate > 0.01
for: 2m → PagerDuty 🔔
▶  Expand full tutorial
01
Pull vs Push: Prometheus scrapes metrics endpoints your app exposes. Add a /metrics endpoint using a client library (Go, Python, Node.js) — Prometheus does the rest.
02
Four Metric Types: Counter (always increases), Gauge (up/down), Histogram (latency buckets), Summary (quantiles). Master these and you can measure anything.
03
Golden Signals: Monitor Latency, Traffic, Errors, and Saturation (the "LTES" signals). Build one Grafana row per service with these four panels minimum.
04
Alerting Hierarchy: Write alerts that page humans only for actionable issues. Route to Slack for warnings, PagerDuty for critical. Use inhibition rules to suppress noise during incidents.
🌿
Version Control
Git
Distributed VCS

The foundation of all DevOps. Git tracks every change to your codebase, enables parallel development via branching, and drives your CI/CD pipeline on every push.

  • Branching strategies: GitFlow, trunk-based
  • Pull requests for code review gates
  • Git hooks for pre-commit automation
  • Signed commits & branch protection rules
# feature branch workflow
$ git checkout -b feature/auth
$ git commit -m "feat: add JWT"
$ git push origin feature/auth
# interactive rebase before PR
$ git rebase -i HEAD~3
$ git push --force-with-lease
▶  Expand full tutorial
01
Commit Hygiene: Write commits in the conventional format: feat: add login, fix: resolve null ref. Tools like semantic-release use these to auto-generate changelogs and bump versions.
02
Trunk-Based Development: Keep branches short-lived (1-2 days max). Merge to main frequently with feature flags to hide incomplete work. This is how elite teams ship fast.
03
Pre-commit Hooks: Use the pre-commit framework to run linters, formatters, and secret scanners on every commit locally — catch issues before CI does.
04
Git Bisect: git bisect start binary-searches your history to find exactly which commit introduced a bug. Invaluable for debugging regressions in large codebases.

Foundation
Linux & Bash
System Mastery

Every cloud server, container, and CI runner runs Linux. Master the shell to automate anything — from log parsing to deployment scripts — in seconds, not hours.

  • Shell scripting with error handling
  • Process management: systemd, cron
  • Networking: ss, iptables, curl, nc
  • Performance: top, vmstat, strace
#!/bin/bash
set -euo pipefail
deploy() {
  echo "Deploying $1..."
  systemctl restart "$1"
  if ! systemctl is-active "$1"; then
    exit 1; fi
}
▶  Expand full tutorial
01
Always use set -euo pipefail: This makes bash scripts exit on errors, unbound variables, and pipeline failures — turning silent failures into loud ones you can debug.
02
Master Text Processing: grep, awk, sed, jq are your Swiss Army knives. Parse logs, transform JSON, extract fields — no Python needed for quick tasks.
03
systemd Services: Write a .service unit file to run your app as a managed system service with automatic restart on crash, log collection, and dependency ordering.
04
Signals & Process Groups: Understand SIGTERM vs SIGKILL. Write signal handlers in your apps to gracefully drain connections before shutdown — critical for zero-downtime deploys.
